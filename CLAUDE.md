## Multi-versions
- `src/main` = la variante de référence **Forge 1.21–1.21.1** (compile telle quelle avec le `build.gradle` racine).
- Les autres cibles sont dans `targets/<cible>/` (build Gradle propre + `target.json` + `overrides/`). Leurs sources sont fabriquées par `python3 tools/port.py <cible>` : blocs `//#if neoforge` / `//#else` / `//#endif` (lignes inactives préfixées `//$$ `), remplacements de `target.json`, puis fichiers de `overrides/`. `python3 tools/port.py --check` vérifie que `src/main` est cohérent.
- Ce qui diffère d'un loader à l'autre passe par `platform/Platform.java`, ce qui diffère d'une version de Minecraft à l'autre par `platform/Compat.java` (une version par cible dans `overrides/` quand il le faut). En 1.20.1 le jeu tourne avec les noms SRG : toute réflexion passe par `Compat.field/method(…, "<nom SRG>")` (correspondances dans `/home/claude/mc/lib-forge-1.20.1/output.tsrg`, bytecode lisible avec `javap -c -p`). En 1.20.1, le bloc `blend` de `screen_fx.json` (override) doit rester celui des shaders vanilla (`add`, `srcalpha`, `1-srcalpha`) : Minecraft ne réapplique le mélange que s'il change, et un autre mode casse le vignettage du HUD (écran noir).
- Compiler une cible localement : `bash /home/claude/tools/compile_target.sh <cible> <release java>` avec les bibliothèques clonées depuis la branche `mc-libs-<cible>` dans `/home/claude/mc/lib-<cible>` (branches produites par le workflow « Export libs » ; les dépôts Maven ne sont pas accessibles depuis la session, GitHub oui).
- 26.x (`targets/neoforge-26.3`, tag `mc26`, Java 25, noms Mojang) : le rendu n'a plus rien à voir (GuiGraphicsExtractor, RenderPipeline, rendu différé, OpenGL **et** Vulkan). Les fichiers trop différents sont remplacés en entier dans `overrides/` (`render/PostFx`, `render/WorldPass`, `render/Overlay`, `render/Pipelines`, `platform/*`) ; le reste passe par les `rewrites` de `target.json`, et `shader_rewrites` adapte les shaders (blocs `//#if mc26` dans `screen_fx.fsh/.vsh`). Les mods sont construits avant l'instance de Minecraft : pas d'`@EventBusSubscriber` pour `Fate`/`ClientSelfTest`, ils sont inscrits dans `FMLClientSetupEvent`. Sources décompilées de référence : `/home/claude/mc/neo263/` ; compiler avec `JAVAC=/home/claude/jdk25/bin/javac bash /home/claude/tools/compile_target.sh neoforge-26.3 25`. En CI, le client 26.x est installé par l'installeur NeoForge (`--installClient`) et testé deux fois (`BACKEND=opengl` avec EGL, `BACKEND=vulkan`).
- CI : un job de build par cible, un job de test en jeu par couple (cible, version du loader) via `tools/ci_test.sh`, puis release (tous les jars) et CurseForge (un fichier par cible, `curseforge/upload.sh`).
- Nouvelle version = augmenter `mod_version` dans `gradle.properties` + ajouter une section `## x.y.z` en haut de `CHANGELOG.md` (elle sert de notes pour la release GitHub et pour CurseForge, envoi automatique).
- Toute nouvelle carte : l'enregistrer dans `card/Cards.java`, l'ajouter dans `tools/lang.py` (FR + EN) puis régénérer les fichiers de langue, et mettre à jour les listes du README et de `curseforge/description.md`. Les malus permanents sont dans `card/Curses.java` (+ `CURSES` dans `tools/lang.py`).
- Les effets d'écran sont dans `assets/fateflip/shaders/core/screen_fx.fsh` (numéros de mode recopiés dans `render/FxPass.java`) ; `tools/fxpreview.py` les rend hors jeu.
- Les cartes ne changent jamais la partie (pas de monstres, pas d'objets) : seulement ce qu'on voit, entend, et la façon dont les commandes répondent. Le mod reste 100 % client.
- Exception validée par Loup0007A : les **malus permanents** (`Curses`) peuvent modifier un peu le jeu du joueur (portée, sprint, déplacements…), mais toujours côté client (rien qui demande le serveur, ex. pas de portée d'explosion des creepers).
- Compiler localement depuis un dossier neutre (`cd /tmp && bash /home/claude/tools/compile.sh`) : le classpath du script se termine par `:` et javac lirait les sources décompilées du dossier courant.
